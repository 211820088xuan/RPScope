# P2 实体消歧设计文档

> 生成时间 2026-08-24 | 信号设计 / 权重 / 兜底率 / 准确率 / 失败case

## 一、设计目标

A 股董监高数据里，同名不等于同一人。"张伟"重名率极高。如果不消歧，连锁董事规则(R4)会产生海量误报，整个系统的 precision 会崩。

消歧的保守原则：**宁可判为不同人（漏），不可误判为同一人（错）**。

## 二、五个信号

| 信号 | 权重 | 逻辑 | 输入 |
|---|---|---|---|
| name_rarity | 0.25 | 姓名稀有度。见<=2家=0.9(稀有), 6-20家=0.35(常见), >20家=0.15(极常见) | name_company_count |
| holding_cross | 0.25 | 两侧都有持股记录(同期)=0.7(同人投资); 不同期=0.5; 一侧=0.5(中性) | 两侧 source+valid_from |
| company_count | 0.20 | 任职广度。<=3家=0.7(可一人), 4-10家=0.5(边界), >10家=0.2(强烈重名) | name_company_count |
| region_match | 0.05 | 公司注册地一致/相邻。**诚实缺口: 无注册地数据, 固定返回0.5(中性)** | 无(缺口) |
| tenure_overlap | 0.25 | 任职时段3年内=0.65(同人可能); >3年=0.3(不同人可能); 不可解析=0.5 | 两侧 valid_from |

## 三、加权融合 + 三档阈值

调优后(P2 银标评测后调参):
- `HIGH_SAME = 0.70`(原0.75) → 规则同人 high
- `LOW_DIFF = 0.40`(原0.35) → 规则不同人 high
- 中段(0.40-0.70) → LLM 兜底 medium/low

调优原因: precision 有 98.2% 巨大余量, 用 -1.2pp precision 换 +15.9pp recall, 净准确率 +11pp。

## 四、LLM 兜底

- 模型: glm-5.2 (经 DashScope 兼容端点)
- prompt: 客观判断(调优后去保守化), 输出 JSON {same_person, confidence, reason}
- 降级: LLM 不可用时保守判不同人 medium
- timeout: 90s/调用(原30s不够, 长文本超时)

## 五、准确率

> **重要声明**: 以下 93.3% 为模型银标(qwen3.7-max 裁判)，且调优时复用了同一批标签(在评测集上调参)，**不作为对外指标**。人工金标准待建。模型标注文件已全部删除(见 T3)。

| 口径 | accuracy | precision | recall | 备注 |
|---|---|---|---|---|
| rule-only(无LLM) | 55.6% | 910.5% | 39.1% | 中段全判不同人→FN多 |
| **含LLM(glm-5.2)** | **93.3%** | 93.9% | 96.9% | TP=62 FP=4 TN=22 FN=2 |
| 银标(qwen3.7-max) | 93.3% | - | - | 独立模型裁判 |
| 交叉(qwen3.7-plus) | - | - | - | 70%与max一致 |

### LLM 兜底率

| 口径 | 兜底率 | 说明 |
|---|---|---|
| 评测集(90对) | 71% | 偏中段采样(故意抽难例) |
| **全图谱(100对)** | **100%** | 信号保守, 中段全覆盖; 93.3%准确率主要靠LLM |

诚实: 信号设计过于保守, 对大多数entity内记录对都返回中段分数(0.40-0.70), 规则无法单独决策。93.3%准确率确实主要靠LLM, rule-only只有55.6%。

## 六、失败case分析

1. **常见名过度拆分**: "深圳市创新投资集团有限公司"(org误标为person)被拆成146个单记录簇——因为它有146条holding记录(持股146家公司), name_rarity返回0.15, company_count返回0.2, 每对score<0.35→全判不同人→过拆。根因: org被标成person + 信号对高频机构实体不友好。

2. **org被标成person**: akshare的股东类型字段对机构实体有时标"自然人", 导致机构走person消歧逻辑。fix应在ingest层修正holder_entity_type。

3. **region_match无效**: 占5%权重但固定返回0.5(中性), 无区分力。需补注册地数据(P0缺口)。
