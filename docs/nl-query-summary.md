# NL2GraphQuery 扩展总结

> 2026-09-01 | 自然语言图查询改造与测试

## 背景

原 Agent 问答链路（classify → route → 单节点 → verify）将问题固定路由到 4 个处理器，能力局限于几个预设问题。本次改造为「自然语言 → 结构化查询 → 确定性执行」，使查询能力可组合、可扩展，覆盖 7 类查询意图。

## 完成的工作

### T1 — 7 类查询模板

定义 7 类意图，每类对应参数化查询模板，配置在 `config/query_templates.yaml`，实现在 `src/query/templates/q1-q7`：

| ID | 意图 | 示例 | 确定性 |
|---|---|---|---|
| Q1 | 查公司关联方 | "比亚迪的关联方" | ✓ 规则引擎 |
| Q2 | 两实体关系路径 | "002594和300750什么关系" | ✓ 规则引擎+图遍历 |
| Q3 | 反向查询 | "王传福控制哪些公司" | ✓ SQL |
| Q4 | 公司角色 | "比亚迪的前十大股东" | ✓ SQL |
| Q5 | 风险事件 | "002594的担保情况" | ✓ SQL |
| Q6 | 关联方重合 | "茅台和五粮液关联方重合" | ✓ 规则引擎 |
| Q7 | 模板外 | "这个股后续增长情况" | LLM 生成 SQL + 三道校验 |

### T2 — 规则意图分类器

- 关键词+正则模式分类，配置在 `config/intent_keywords.yaml`
- 100 条测试集（`tests/query/test_intent_data.py`），每类 ≥10 条
- **准确率 100%**，LLM 兜底率 0%（目标 ≥80%）
- 测试中发现并修复：Q3 缺"持股"关键词 → 已补

### T3 — 槽位抽取与实体链接

- 槽位抽取：LLM 输出严格 JSON，uncertain 时与意图分类合并为一次调用
- 实体链接 5 级匹配：代码 → 简称 → 全称 → 归一化 → 模糊
- 澄清机制：多候选拿不准时返回澄清请求，不自选最高分
- 测试中发现并修复：公司简称（如"中国平安"）在 entity 表无精确匹配 → 加 company 表预查 + 按 holding 记录数选主体

### T4 — 模板外查询生成

LLM 生成 SQL，经三道校验后执行：
- 结构校验：表名/列名白名单
- 只读校验：禁写操作
- 资源约束：强制 LIMIT ≤200

校验失败带错误重试，最多 2 次；结果标记 `source: "generated_query"`。

### T5 — Agent 链路改造

LangGraph StateGraph，流程：
```
规则分类 → 槽位抽取 → 实体链接 → {模板执行 | 澄清 | 模板外生成} → 回答生成 → 回查
```

### T6 — trace 埋点

每次查询写入 `.cache/traces/{hash}.json`，记录从问句到答案的完整链路。
