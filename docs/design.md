# RPScope 设计取舍与技术报告

## 1. 为什么 LLM 不参与关联方判定（核心架构主张）

关联方判定的输出是**有法律含义的事实断言**——"A 与 B 构成关联方"会触发披露/审议义务。事实断言必须可回溯到具体数据行（哪份年报、哪期股东表、哪条规则），不能来自概率生成模型。

所以判定 100% 走确定性规则 + Cypher/networkx 查询（R1-R7），LLM 完全挡在判定逻辑之外。LLM 只在三处出现，且边界清晰：

| 位置 | 任务 | 失败降级 |
|---|---|---|
| 实体消歧兜底 | 多信号无法判定的同名候选 | 判为不同人（保守，宁漏不错） |
| 公告事件抽取 | 从公告文本抽关联交易/担保 | 跳过该文档 |
| 报告撰写 | 把结构化结论写成自然语言 | 退回模板 |

**LLM 碰不到判定的地方，就不存在幻觉。** 判定环节 LLM 调用数=0 是可验证的硬约束（P3 单测 + 运行时 metrics）。

撰写环节也做断言级回查：抽答案里的实体名/数字，逐一比对是否在输入结构化数据里存在，不存在的整段重写或降级模板。回查通过率是可写简历的指标（P8 实测 100%）。

## 2. 数据可行性的真实分布决定方案（P0 探针的价值）

P0 探针在写业务代码前先验证了真实数据分布，避免"做三周才发现图上没有可跳的路径"的最大死法。关键发现：

- **R3 共同股东近乎失效**：排除通道后 50 家最密公司仅 0.3% 对有非通道共同股东。这是 A 股市场结构事实（关联性由实控人/董监高承载），不是数据缺失。**方案调整**：R3 降级 low-confidence 上下文，R2(同一控制)+R4(连锁董事) 升为双核心。准则第36号第六条第(二)项也印证单纯持股重叠不必然构成关联方。
- **通道排除是项目死法之一**：首轮"香港中央结算"度数 2645 会把全 A 股连成一坨。4 轮迭代（ETF 中文名/社保全名/QFII 无空格/HKSCC 变体/**政府控制人**）后降到 74。
- **政府控制人排除**：准则"同受国家控制的企业之间不构成关联方"。各级国资委若不排会把所有国企两两相连（国务院国资委原度数 287）。这是 domain know-how 不是 hack。

## 3. 评测用外部金标准而非自建题（可信度关键）

不自己造题，拿上市公司年报披露的关联方清单作外部基准。但年报金标准有微妙性：它披露的是公司**自己认定并愿意披露**的，系统发现但年报未披露的可能是①真漏报/隐瞒（系统价值）②不满足披露实质标准③系统误报。所以必须三分类人工核查，不能简单把"系统发现未披露"算 FP。P5 的 208 条 system_only 待人工分开（其中 R2 的 149 兄弟公司按准则本就是关联方，若 gold 真未披露则是系统发现隐瞒=价值）。

## 4. 已知限制（诚实边界）

- 图谱上行完整、下行残缺：公开接口只到十大股东（上行），子公司/联营（下行）需工商数据或年报"主要子公司"章节，未覆盖。→ recall 1.3% 的结构性根因，金标准映射率 5% 的根因。
- 批量接口无 ratio：R1/R3 的 ≥5% 判定在 Dev/Eval 集用个股接口（有 ratio，1.4s/家）。
- 担保接口仅聚合：成对担保边需 P6 从公告文本抽对手方。
- 人名消歧依赖信号质量：region 信号无注册地数据（中性），靠姓名稀有度/持股交叉/任职广度/任期。

## 5. 与已有图谱项目的关系

之前在实验室做过知识图谱驱动的模糊测试生成（重心在图谱构建+多智能体编排）。本项目刻意换重心——图谱只是底座，真正花时间在：监管口径→可执行规则的翻译、中文人名消歧、外部金标准评测方法。同一套图谱+校验方法论，不同领域的投入方向不同：代码域难点在构图，金融域难点在口径与评测。

## 6. 工程化取舍

- **存储**：机器无 Docker，P1 起临时 SQLite(事实源)+networkx(图视图)，抽象在 `src/store`/`src/graph`，PG/Neo4j 就绪后换仅重写 query 层。
- **LangGraph**：意图路由+回查逻辑用 LangGraph StateGraph 编排（纯 Python 装得快，不要因"可能慢"绕开标准栈）。
- **成本控制**：让 LLM 少干活（规则优先/意图路由/消歧分级/缓存/JSON/模板降级）。单次底稿≈0.011 元，判定环节 LLM=0。
